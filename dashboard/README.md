# Scout Dashboard

Admin web dashboard for Scout — React 19 + TypeScript + Vite.

## Requirements

- Node 24 (`nvm use` reads `.nvmrc`)

## Commands

| Command             | What it does                                  |
| ------------------- | --------------------------------------------- |
| `npm run dev`       | Start the dev server on http://localhost:5173 |
| `npm run build`     | Type-check and build to `dist/`               |
| `npm test`          | Run unit and component tests (Vitest)         |
| `npm run coverage`  | Tests with a coverage report                  |
| `npm run lint`      | Lint with oxlint                              |
| `npm run typecheck` | TypeScript only                               |
| `npm run format`    | Format with Prettier                          |

## Stack

React Router · TanStack Query · react-hook-form + zod · shadcn/ui (Radix, RTL) + Tailwind CSS 4 · i18next (English / Arabic) · Recharts · Vitest + Testing Library + MSW.

## Structure

```
src/
  app/          # providers, routes, nav config (roles), layout (sidebar, top bar)
  components/   # shared components; ui/ is generated by shadcn (don't edit by hand)
  features/     # one folder per area: auth, profiles, plans, … (pages, hooks, schemas, tests)
  lib/          # i18n, utils, API client (later)
  locales/      # en.json, ar.json — keep keys identical (a test enforces it)
  test/         # test setup and helpers
```

The current build is the **clickable build on mock data** (no API yet): mock login (any valid email signs in as a super admin), role-based menu, and a working screen for every section, including Reels moderation. Mock data lives in `src/mock/`, shaped like the Flutter app models. Moderation actions (approve, reject, hide, suspend, extend, featured) change the in-memory state and are written to the Audit log.

**Reel rules (from the dev note):** a user can upload at most 35 reels per month, each reel is at most 2 minutes long, and approved reels stay in the app with no expiry. The limits are constants (`REEL_MAX_PER_MONTH`, `REEL_MAX_SECONDS`) in `src/mock/data.ts`. The reel review screen shows the owner's uploads this month against the limit, and Settings states the rules. The backend must enforce the limits on upload, because the dashboard only displays them.

**Source of truth:** the approved mobile design (`Scout.pdf`), then the SRS. Plan names and prices (6 months 36 KWD, 1 year 60 KWD, Featured 1 month 5 KWD, 3 months 20 KWD), payment methods (KNET, Apple Pay, Visa, MasterCard via MyFatoorah), coupon behaviour and the Contact Us texts follow the app.

Mismatches between the mobile design and the rules the dashboard follows are listed in [docs/design-corrections.md](docs/design-corrections.md).
